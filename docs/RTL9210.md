# Realtek RTL9210 profile

The physically accepted reference enclosure identifies through a Realtek
RTL9210 USB-to-NVMe bridge. On that platform, suspend caused the bridge to
disconnect and later re-enumerate, potentially under a different `/dev/sdX`
name. GNOME/udisks could then treat the partitions as newly attached removable
media.

The `rtl9210` profile is selected when discovery sees USB vendor/product
`0bda:9210`. The safety mechanism does not trust that bridge ID alone: the
underlying storage serial and exact filesystem UUID set must also match, and
each runtime generation is bound to sysfs, `diskseq`, udev properties, and
major:minor numbers.

The profile does not claim all RTL9210 firmware, enclosures, cables, NVMe media,
or USB controllers behave alike. Firmware revisions are not normalized enough
to infer safety from the chipset name. Perform a supervised acceptance cycle on
each hardware configuration after validating backups.

Generic USB-storage discovery is available by design, but physical acceptance
in v1.0.0 covers only the reference RTL9210 platform described in
[TESTED-HARDWARE.md](TESTED-HARDWARE.md).
