# Production transaction adapter

The reference host has a legacy V2 storage/T700 installation separate from the portable distribution. `aag-sleep-transaction` integrates that installation through SHA256-pinned adapters and gives ordinary suspend a single transaction owner. Use `scripts/deploy_transaction.py` only with an inspected host configuration and a private report directory; it is not an automatic replacement for the portable installer. The installed configuration is root owned and mode 0600.

The transaction journal distinguishes accepted requests, kernel entry/exit, completed kernel cycles, measured hardware residency, and verified restoration. Old failures are reconciled before creating a new transaction. Retry accounting belongs to that transaction. A failed or stale callback cannot claim a new transaction. A recovery inhibitor includes `handle-lid-switch`, because a high-level sleep inhibitor alone does not suppress default logind lid handling.

Known checkpointable workloads have declarative detection, stop, verification, timeout and restore policies. These APIs are preferred, but an application registry is not required. Exact ordinary userspace blockers receive SIGTERM, a bounded wait, and SIGKILL only if they still hold the resource and remain safe to terminate. A pinned pidfd, process start time, executable and privilege checks prevent stale audit records from authorizing a signal to a replacement process. The audit verifies release after stopping; a successful command is not sufficient. Unknown ordinary user applications use this same policy.

PID 1, kernel threads, the transaction's control processes, storage/filesystem infrastructure, databases, package transactions, virtual machines and unclassified privileged services are excluded from forced termination. A critical blocker can use a configured supported shutdown mechanism. The reference host's guest integration requests ACPI shutdown without a forced guest timeout or USB detach. If safe shutdown is unavailable or does not release the resource, the transaction fails visibly and retains real thermal/battery supervision. An ordinary noncritical container needs no application allowlist; its privilege setting and member processes are checked before signalling an exact blocker.

USB mass-storage gadgets additionally need device, namespace and guest ownership checks. The configured USB Clone command runs only after proving there are no live USB/backing-file consumers and cleanly releasing host mounts. User image contents are preserved. Internal DATA remains mounted because it is not the external device being removed. Workloads with user-stop semantics and terminated ordinary processes are not automatically restarted.

At normal temperature, exhausting one retry does not cause automatic shutdown. Measured thermal emergencies, critical discharging battery, and sustained closed-lid loss of thermal telemetry retain a recorded safety fallback. Device-policy undo invokes the existing restore function directly, never a legacy callback that can power off.

`systemd/production/` contains override fragments for the reference adapter. The native systemd-sleep executor and accepted storage guard remain unchanged. Device health verification retains the pinned hardware, kernel, storage, policy and cellular checks while recording long-cycle qualification separately. A short cycle or a closed lid does not by itself create a device-health latch. A healthy wake with the lid still closed enters the same one-retry recovery policy. A narrow LockLock compatibility module verifies the replacement graph and requires a fresh, completed transaction with actual sleep; it preserves LockLock's ownership of intentional lid-ignore and safety supervision. Its two dispatches in `input_lock_safety.py` retain the legacy fallback when the adapter is absent. Hibernate is not automatically substituted and its strict qualification must be reviewed when the surrounding graph changes.

`scripts/accept_transaction.py` runs one explicitly authorized RTC-backed acceptance cycle, including stale-state reconciliation and safe handling of real blockers. Automated tests do not qualify hardware behavior. Physical lid-close/open acceptance must be recorded separately from an open-lid timed-wake test.

The deployment manifest records source/installed hashes and the exact previous files. Rollback restores only those files and the enablement link, then reloads unit definitions. When several candidate deployments were applied, restore manifests in reverse deployment order to reach the original installation, including the original LockLock interface. Reload the affected daemon only while its controls are idle. Keep private identities, logs, workload paths and host policy outside public Git history. No public release is implied by local installation.
